## The contract audited against

1. **One click semantic per surface:** click = select + reveal (+ seek where a
   playhead exists); selecting never changes view; view changes are labeled
   verbs only.
2. **Arrivals reveal, returns restore:** every cross-view jump lands selected +
   scrolled-into-view; returning restores selection AND viewport.
3. **Disclosure is local:** any expand/collapse moves only content below it in
   its own panel; the toggle stays under the cursor; page scroll survives;
   nothing elsewhere reflows.
4. **Scale degrades honestly:** lists that can reach ~1000 items and timelines
   that can reach hours have a declared strategy; measure, don't guess.
5. **What you write, you can find again:** every annotation affordance has a way
   to LIST what was written.

Session facts (demo): 155 raw events · 64 steps · 4 cases · 10 vocabs · no
recording. Level buttons present: `overview` (default) / `flow` / `steps` /
`phases` / `map` — Analysis is folded into Overview (R4), there is no separate
`analysis` level button.

## J. Scale probe

**Method (paste-verifiable).** `build-big.js` (scratchpad, outside the repo)
reads the demo `events.jsonl` (155 events) and repeats it **N=15** times, each
repetition shifted by `r × 15 min`, every event given a fresh 16-byte hex id,
each case-start label suffixed `r0…r14`, `session_start`/`session_end` kept once,
then re-sorted monotonically. Result: **2297 raw events, span
09:00:00→12:35:42 = 3.60 h**. Re-analyzed with
`viewer/python/python.exe normalization/normalize.py … --mine` (≈5 s). Pipeline
output (from `stats.json` / `annotations.json`): **960 steps, 60 cases**
(315 activity events after normalization). Loaded into the viewer and measured:

| Metric | Number | Note |
|---|---|---|
| Steps flat list render | **48 ms** | element grain |
| Steps flat DOM rows | **960 of 960** (ratio 1.00) | **NO virtualization / cap** — every step is a live `.step-row`. Mitigated only by a fixed-height scroll panel (`#step-list`), not windowing. Confirmed in code: `renderStepList` maps all filtered steps to rows. |
| Case tree render | **50 ms** | 60 case heads, 0 item rows (lazy — items render only on expand). **This is the honest degrade for Steps.** |
| Flow timeline initial paint | **65 ms** | 315 activity bands, 60 case bands + **60 case labels**, 285 step bands, 240 minimap bands, timeline width 1527px |
| Filter keystroke → list update | **≈210 ms** end-to-end ("SAP" 960→225; "Excel" 960→240), incl. a 120 ms debounce | input id is `#step-filter-text`; responsive at 960 steps |
| Overview render | **15 ms** | — |
| Total DOM nodes | **36 405** | `document.querySelectorAll('*').length` |
| JS heap | **18 MB** | `performance.memory.usedJSHeapSize` |

**What visibly strains (screenshots in scratchpad):**
- `scale-flow.png` — the Flow timeline is **legible but crowded**: 60 case bands
  packed into ~1500px render as densely repeating truncated labels ("Order
  #10902 C C ( Order #10902 …") that overlap. Ticks/minimap/lanes stay clean.
- `scale-steps-flat.png` — 960 rows sit in a scrollable left panel; legible,
  the mini-timeline compresses into rhythmic clusters.
- `scale-steps-tree.png` — 60 collapsed case rows, one line each ("Order #10900
  r0 · 5 items · 20.0s"); clean. **The case tree is the graceful default.**
- `scale-overview.png` — Overview unaffected.

**Declared strategy verdict:** Steps has a real strategy at the **screen notch**
(lazy case tree) but the **element-notch flat list is unbounded** (960 live
rows). The Flow timeline has no thinning for **case-label density** (60 labels
overlap). Nothing errored or froze at 960 steps / 3.6 h, but the flat list and
the case-label lane are the two surfaces that will degrade first past this size.

## Top frictions ranked

1. **App-library rail button is dead** (§D1) — "Open the App Library" calls a
   non-exported `activateTab` on the wrong require, throws silently, navigates
   nowhere. The one rail act that can't reach its target.
2. **Map nodes are non-interactive at the default (screen) notch** (§E1) — a
   node click does nothing, yet the shortcuts overlay says "Click node → Drill
   into details." The default map surface looks interactive but isn't.
3. **Steps-lane band click is an unlabeled view change** (§A3) — a plain click
   on the timeline's steps lane silently switches Flow→Steps, violating "view
   changes are labeled verbs only."
4. **Side-by-side compare has no inverse** (§G3) — once opened it cannot be
   closed; re-clicking the button does nothing and its label never toggles.
5. **Activity-frequency chart bars advertise `.clickable` but do nothing** (§G6)
   — misleading affordance in the Compare exploration drawer (the real drill is
   on the map).
6. **Flat step list has no virtualization** (§J) — 960 steps = 960 live DOM
   rows (36 405 nodes total); it renders in 48 ms today but is the first surface
   to strain past ~1000 steps.
7. **Map "Advanced views" drawer steals map height and moves its own toggle**
   (§E2, §I) — opening it shrinks the map host −47px rather than growing the
   page; the toggle jumps out from under the cursor.
8. **Activity and case bands seek but never select** (§A1/§A2) — the timeline's
   most-clicked targets give a playhead-only response; there is no selection
   handle, and a case band's click (seek) and right-click (scope) disagree.
9. **Case-label density on the Flow timeline** (§J) — 60 case labels overlap
   into unreadable repetition at a multi-hour span; the case lane has no
   label-thinning.
10. **Memo selection is write-only-until-export** (§K) — the analyst's
    include-in-memo choices have no aggregated on-screen list; the assembled
    memo only exists in the exported file.
11. **"Raw events" drawer reflows its own summary** (§D13, §I) — opening it on
    Flow jumps the toggle −24px (flex rebalance); minor but a disclosure that
    doesn't stay under the cursor.
12. **EXPLORATION drawer defaults open** (§G4) — a Machine-altitude drawer that
    ships expanded, against the DISCLOSURE-MODEL "collapsed by default" rule.
