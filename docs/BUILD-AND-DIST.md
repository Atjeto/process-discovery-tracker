# Build pipeline and dist layout

A quick reference for where binaries come from, where they land, and how a release reaches users.

## The two apps

| App | Source dir | Launcher (after install) |
|---|---|---|
| Capture (worker tray) | `capture/` | `Process Discovery Tracker.exe` |
| Viewer (analyst UI) | `viewer/` | `Process Discovery Viewer.exe` |

## Distribution model

Prebuilt binaries live on **GitHub Releases**, not in git. The repo only carries source. To get the apps onto a fresh machine:

1. Open the [Releases page](../../releases) for the latest tag.
2. Download `capture-vX.Y.Z.zip` and `viewer-vX.Y.Z.zip`.
3. Unzip wherever; run the `.exe` inside. No installer.

Local `capture/dist/` and `viewer/dist/` folders are gitignored. They're produced by the build script for local testing and as the inputs to `dist/release/*.zip`.

## The C# recorder sidecar

The capture app spawns a self-contained .NET 8 single-file executable (`recorder.exe`, ~160 MB) that owns the UIA event subscription. It travels with the capture app inside `resources/publish/`.

### Where recorder.exe lives, and why

| Path | Role | Tracked? | Cleaned up? |
|---|---|---|---|
| `capture/recorder/bin/` | `dotnet build` intermediate (split DLLs). Build slag — nothing consumes it. | gitignored | Safe to `rmdir /s /q` any time; regenerated by next `dotnet publish`. |
| `capture/recorder/obj/` | `dotnet` intermediate object cache. | gitignored | Safe to delete. |
| `capture/recorder/publish/recorder.exe` | Canonical output of `dotnet publish -c Release -o recorder/publish`. Self-contained, single-file. Consumed by `electron-packager` via `extraResource`. | gitignored | Regenerated by `npm run build:recorder` or `npm run package`. |
| `capture/dist/.../resources/publish/recorder.exe` | The copy that ships inside the packaged Electron app, then gets zipped into `dist/release/capture-vX.Y.Z.zip` for the GitHub Release. | gitignored | Regenerated by `npm run package`. |

### Runtime resolution

`capture/recorder.js → resolveRecorderPath()` checks, in order:

1. `$env:PDT_RECORDER_PATH` (dev override).
2. Packaged: `resources/recorder/recorder.exe`, then `resources/publish/recorder.exe`.
3. Source tree: `capture/recorder/publish/recorder.exe`.
4. **Fallback**: if none of the above exist but a `recorder.zip` sits next to where an .exe would land, extract it in place via `tar.exe -xf` (Windows 10+ ships libarchive-backed tar that handles zip).
5. Throw "recorder.exe not found ... (and no recorder.zip to extract)".

The auto-extract step is a safety net — it should rarely fire now that Releases ship the .exe unzipped, but it costs nothing and protects against future packaging surprises.

## Build pipeline

```
                          npm run package (capture/)
                          ─────────────────────────────
                          1. prepackage: dotnet publish -c Release -o recorder/publish
                                         → recorder/publish/recorder.exe  (~160 MB)
                          2. electron-packager:
                              - copies app + node_modules into dist/.../resources/app.asar
                              - --extra-resource recorder/publish
                                  → dist/.../resources/publish/recorder.exe

                          npm run package (viewer/)
                          ─────────────────────────
                          1. electron-packager:
                              - copies app + node_modules into dist/.../resources/app.asar
                              - --extra-resource python/        (bundled Python embeddable)
                              - --extra-resource normalization/ (staged copy of root normalization/)

                          scripts/build-distribution.ps1
                          ──────────────────────────────
                          1. scripts/build-python-embeddable.ps1 (~3-5 min) writes viewer/python/.
                          2. Stages root normalization/ into viewer/normalization/.
                          3. npm run package (capture)   → capture/dist/.../
                          4. npm run package (viewer)    → viewer/dist/.../
                          5. Assembles dist/{capture,viewer,SBOM.json,DISTRIBUTION.md,...}.
                          6. Zips each app folder into dist/release/<name>-v<version>.zip.

                          scripts/publish-release.ps1 -Version 0.2.0
                          ──────────────────────────────────────────
                          Wraps `gh release create vX.Y.Z <assets>`. Requires gh CLI.
                          Manual equivalent:
                            gh release create v0.2.0 dist\release\*.zip --title "..."
```

## What's safe to delete

When the disk is full and you need to reclaim space:

| Path | Approx size | Regen by |
|---|---|---|
| `capture/recorder/bin/` | ~150 MB | `dotnet publish` (next build) |
| `capture/recorder/obj/` | ~50 MB | `dotnet publish` (next build) |
| `capture/recorder/publish/` | ~160 MB | `npm run build:recorder` |
| `capture/dist/` and `viewer/dist/` | ~600 MB | `scripts/build-distribution.ps1` |
| `viewer/python/` | ~450 MB | `scripts/build-python-embeddable.ps1` (3-5 min) |
| `dist/` (root) | ~700 MB | `scripts/build-distribution.ps1` |

Everything under those paths is gitignored, so deleting them never affects history.

## .gitignore rationale

The root `.gitignore` ignores `node_modules/`, `dist/` and `build/` at the repo root (with the leading slash) so they survive inside `node_modules/<pkg>/...` — electron-packager honors `.gitignore` rules and would otherwise strip bundled assets from `obs-websocket-js`, `bpmn-js`, and `cytoscape` from the asar.

`capture/dist/` and `viewer/dist/` are explicitly ignored so build outputs never get accidentally committed. The C# recorder's `bin/`, `obj/`, and `publish/` folders are ignored via `capture/recorder/.gitignore`.
