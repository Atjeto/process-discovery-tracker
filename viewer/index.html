      How to use
      
        
      
      
      
      
        
        
        
        
        
        
        
      
      
      
      

        
      
          
      From a recording to the PDD
      
          
      The SME records the process a few times, one run each time, and sends you the recording folder. You confirm the first run's drafted steps, review how the other runs differ, write the document and export the PDD. The Overview's What is left line shows where you are, with one button for the next act.
      
          
        
            
      1. Runs. Open the recording: the app analyzes it by itself and drafts each run's steps and the map (the bar at the top says so while it works). Each run starts at a start marker; if one is missing, add it on the Timeline (right-click the timeline at that moment) and click Apply marker changes.
        2. 
            
      2. Reference run. In Steps, check run 1's drafted steps against the screenshots or the video. Fix the boundaries (merge, split, add, hide), name the steps the way the document should, write a description where a step needs one, then click Confirm run.
        3. 
            
      3. Other runs. The other runs arrive drafted and named like the reference run. Review the differences each one lists (extra, skipped or reordered steps) and confirm it.
        4. 
            
      4. Document. On the Overview, write the document fields: title, purpose, scope, trigger, result, contacts, business rules, exceptions and the improvement and automation scope. The PDD prints them in place of its placeholders.
        5. 
            
      5. PDD. Export the PDD (.docx). Its process map is your edited As-Is map when you made one (on the Map, Edit as the As-Is map), else the map from the runs. Save as this process on the confirmed pattern run lets the next recording of the same process arrive drafted and named.
        6. 
          
      
          
      Optional inputs
      
          
        
            
      • A video of the recording, for example a Teams recording: attach it on the Overview's recording line or on the Timeline's video band, to check the steps against it and hear the SME explain. You sync it as you attach it: pause it at a moment you recognize, then click the same moment on the timeline.
        • 
            
      • A meeting transcript (.vtt or .docx): attach it on the Overview's recording line. Its sentences show next to each step and beside the document fields, ready to add to a step's description or a field.
        • 
          
      
        
      

        
      
          
      Runs and drafted steps
      
          
      A run is one pass through the process, from a start marker to its end marker. The app drafts every run's steps: a step is one visit to a screen, and it ends at the action that commits the work there (Save, Search, Submit, Send) or where the work moves to another screen. Steps lists the runs in time order; open a run to see its steps. Steps outside every run are listed under Outside runs.
      
          
      Confirm the pattern run first
      
          
        
            
      1. Open the pattern run: run 1, marked Pattern, unless you choose another one.
        2. 
            
      2. Check its steps against the screenshots or the video. Where a boundary is wrong, merge, split, add or hide steps (right-click a step, or use the step pane).
        3. 
            
      3. Name the steps the way the document should: double-click a name, or select the step and press Enter. A step's description is printed with it in the PDD.
        4. 
            
      4. Click Confirm run: the steps you did not change are accepted as they are. Reopen run takes the confirmation back.
        5. 
          
      
          
      Fixes that carry to the other runs
      
          
      A merge in the pattern run is also made in the other runs wherever they have the same drafted steps one after the other, and one Ctrl+Z undoes all of it. Hiding a drafted step offers to hide it in every run. Splits and added steps are made in each run that needs them.
      
          
      Differences between runs
      
          
      Every other run is compared with the pattern run step by step, the way the PDD compares them: an open run lists its extra steps (and where they happen), its skipped steps and the steps done in a different order.
      
          
      Saved names
      
          
      A name you give a drafted step goes at once to the same drafted steps in the other runs, and this computer saves it: the next analysis of this recording or a later one drafts those steps with it (a small remembered tag). Saved names, in the Steps toolbar, lists them: rename one, or forget it.
      
          
      Saved processes
      
          
      Once the pattern run is confirmed, Save as this process keeps its steps on this computer. A later session of the same process is compared with the saved process until its own pattern run is confirmed.
      
          
      What the step labels mean
      
          
      A step shows its label only where it differs from its run: the run's status (Draft or Confirmed) says it for the others. Steps outside every run show theirs.
      
          
        
            
      • Draft drafted by the app and not checked yet; every analysis drafts it again.
        • 
            
      • Confirmed you accepted the draft as it is.
        • 
            
      • Edited you changed its name, its boundaries or its flags.
        • 
            
      • Added you added it by hand.
        • 
            
      • Hidden you took it out; Show hidden steps on its run lists it again.
        • 
          
      
          
      Every analysis keeps confirmed, edited, added and hidden steps as they are.
      
          
      Leaving things out
      
          
        
            
      • Leave apps out, in the Steps toolbar: tick the apps that are not part of the process; the steps and the map are updated without them.
        • 
            
      • Hide step: takes one step out, and no analysis brings it back. Only a step you added can be deleted.
        • 
          
      
          
      Waste
      
          
      Flag a step as Waste when it should not be needed (rework, duplicate effort). The PDD prints the flag with the step. Branches, exceptions and automation candidates are not flags: they come from the recorded runs.
      
        
      

        
      
          
      Working with markers
      
          
      A run starts at a start marker and ends at its end marker; the SME places them with the recording keys. An edited marker changes the runs once you apply it; the recording itself never changes.
      
          
        
            
      • Add: right-click the timeline at that moment and insert a Start or End marker.
        • 
            
      • Rename, move or delete: in the Timeline's Markers panel. Double-click a Start marker to rename it.
        • 
            
      • Apply: a changed marker shows at once as pending. Apply marker changes, in the bar at the top, updates the runs, the steps and the map.
        • 
          
      
          
      To join two runs, delete the End of the first and the Start of the second. To split a run, move its End earlier and insert a new Start after it.
      
        
      

        
      
          
      What to tell the SME
      
          
      The SME records with the capture app on their own computer. These keys mark the runs while recording:
      
          
      
            
      Ctrl+Shift+SStart the next run (Run 1, Run 2, and so on). Ends the previous run first, and starts the recording if none is running.
      
            
      Ctrl+Shift+EEnd the current run.
      
            
      Ctrl+Shift+PTake a screenshot by hand.
      
          
      
        
      

        
      
          
      Keyboard shortcuts
      
          
      
            
      SpacePlay or pause the video
      
            
      ← →Move the video 5 seconds (hold Shift for 10)
      
            
      + − 0Zoom the timeline in, out, or back to the whole recording
      
            
      Ctrl+ZUndo the last edit
      
            
      Ctrl+Y / Ctrl+Shift+ZRedo
      
            
      ↑ ↓ (Steps)Previous or next step of the open run
      
            
      Enter (Steps)Rename the selected step
      
            
      S / M (Steps)Split the selected step, or merge it with the next step of its run
      
            
      Ctrl+Enter (Steps)Confirm the open run
      
            
      ?Open this help
      
            
      EscClose this help
      
          
      
          
      Undo covers every edit (steps, markers, document fields, maps), up to 50, until you open another recording.
      
          
      Clicks
      
          
        
            
      • Click a band, a marker or a screenshot on the timeline to go to that moment.
        • 
            
      • Right-click the timeline to insert a Start or End marker there.
        • 
            
      • While the steps and the map are updated, the bar at the top says so, with Cancel.
        • 
          
      
        
      

        
      
          
      Common issues
      
          
      
            
      A recording key did nothing
      
            
      Another program on the SME's computer may use the same keys. Close it and press the key again, or use Start next run and End run in the capture app's tray menu.
      

            
      A Citrix or remote desktop window shows as one app
      
            
      The recorder cannot see inside a remote window from the SME's computer, so the work done in it shows as one app with no steps inside. Run the capture app inside the remote session, or rely on the run markers and a video for that part.
      

            
      The steps or the map are missing or out of date
      
            
      The app analyzes a recording by itself when it opens. If that stopped (it was cancelled, or it failed and the log at the top says why), analyze it again. Your confirmed, edited, added and hidden steps are kept.
