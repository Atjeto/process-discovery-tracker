      How to use
      
        
      
      
      
      
        
        
        
        
        
        
        
      
      
      
      

        
      
          
      From a recording to the PDD
      
          
      The SME records the process a few times, one run each time, and sends you the session folder. You confirm the first run's drafted steps, review how the other runs differ, finish the map and export the PDD. The Overview's What is left line shows where you are, with one button for the next act.
      
          
        
            
      1. Runs. Open the session folder and click Analyze session. Each run starts at a start marker; if one is missing, add it in Flow (right-click the timeline at that moment) and analyze again.
        2. 
            
      2. Pattern run. In Steps, check run 1's drafted steps against the screenshots or the video. Fix the boundaries (merge, split, add, hide), name the steps the way the document should, add a note where a step needs one, then click Confirm run.
        3. 
            
      3. Other runs. The other runs arrive drafted and named like the pattern run. Review the differences each one lists (extra, skipped or reordered steps) and confirm it.
        4. 
            
      4. Document. On the Overview, write the document sections: title, purpose, scope, contacts, business rules and exceptions. The PDD prints them in place of its placeholders.
        5. 
            
      5. As-Is map. On the Map, fork the map into an editable As-Is copy and finish it in the map editor. The PDD embeds it as its As-Is map.
        6. 
            
      6. PDD. Tick the findings the PDD should print, then export the PDD (.docx). Save as this process on the confirmed pattern run lets the next recording of the same process arrive drafted and named.
        7. 
          
      
          
      Optional inputs
      
          
        
            
      • A video of the session, for example a Teams recording: attach it from the More menu to check the steps against it and hear the SME explain.
        • 
            
      • A meeting transcript (.vtt or .docx): attach it from the More menu. Its sentences show next to each step and beside the document sections, ready to add to a step note or a section.
        • 
          
      
        
      

        
      
          
      Runs and drafted steps
      
          
      A run is one pass through the process, from a start marker to its end marker. Analyze session drafts every run's steps: a step is one visit to a screen, and it ends at the action that commits the work there (Save, Search, Submit, Send) or where the work moves to another screen. Steps lists the runs in time order; open a run to see its steps. Steps outside every run are listed under Outside runs.
      
          
      Confirm the pattern run first
      
          
        
            
      1. Open the pattern run: run 1, marked Pattern, unless you choose another one.
        2. 
            
      2. Check its steps against the screenshots or the video. Where a boundary is wrong, merge, split, add or hide steps (right-click a step, or use the step pane).
        3. 
            
      3. Name the steps the way the document should: double-click a name, or select the step and press Enter. A step's note is printed with it in the PDD.
        4. 
            
      4. Click Confirm run: the steps you did not change are accepted as they are. Reopen run takes the confirmation back.
        5. 
          
      
          
      Fixes that carry to the other runs
      
          
      A merge in the pattern run is also made in the other runs wherever they have the same drafted steps one after the other, and one Ctrl+Z undoes all of it. Hiding a drafted step offers to hide it in every run. Splits and added steps are made in each run that needs them.
      
          
      Differences between runs
      
          
      Every other run is compared with the pattern run step by step, the way the PDD compares them: an open run lists its extra steps (and where they happen), its skipped steps and the steps done in a different order.
      
          
      Names are remembered
      
          
      A name you give a drafted step goes at once to the same drafted steps in the other runs, and this computer remembers it: the next analysis of this session or a later one drafts those steps with it (a small remembered tag). Remembered names lists them: rename one, or forget it.
      
          
      Saved processes
      
          
      Once the pattern run is confirmed, Save as this process keeps its steps on this computer. A later session of the same process is compared with the saved process until its own pattern run is confirmed.
      
          
      What the step labels mean
      
          
        
            
      • Draft drafted by the app and not checked yet; every analysis drafts it again.
        • 
            
      • Confirmed you accepted the draft as it is.
        • 
            
      • Edited you changed its name, its boundaries or its flags.
        • 
            
      • Added you added it by hand.
        • 
            
      • Hidden you took it out; Show hidden steps on its run lists it again.
        • 
          
      
          
      Every analysis keeps confirmed, edited, added and hidden steps as they are.
      
          
      Leaving things out
      
          
        
            
      • Ignored apps: tick the apps that are not part of the process; the session is analyzed again without them.
        • 
            
      • Hide step: takes one step out, and no analysis brings it back. Only a step you added can be deleted.
        • 
          
      
          
      Waste
      
          
      Flag a step as Waste when it should not be needed (rework, duplicate effort). The PDD prints the flag with the step. Branches, exceptions and automation candidates are not flags: they come from the recorded runs.
      
        
      

        
      
          
      Working with markers
      
          
      A run starts at a start marker and ends at its end marker; the SME places them with the recording keys. An edited marker changes the runs once the session is analyzed again; the recording itself never changes.
      
          
        
            
      • Add: right-click the Flow timeline at that moment and insert a Start or End marker.
        • 
            
      • Rename, move or delete: in Flow's Markers panel. Double-click a Start marker to rename it.
        • 
            
      • Apply: a changed marker shows at once as pending. Analyze to apply on the actions bar (or Analyze session) updates the runs, the steps and the map.
        • 
          
      
          
      To join two runs, delete the End of the first and the Start of the second. To split a run, move its End earlier and insert a new Start after it.
      
        
      

        
      
          
      What to tell the SME
      
          
      The SME records with the capture app on their own computer. These keys mark the runs while recording:
      
          
      
            
      Ctrl+Shift+SStart the next run (Run 1, Run 2, and so on). Ends the previous run first, and starts the recording if none is running.
      
            
      Ctrl+Shift+EEnd the current run.
      
            
      Ctrl+Shift+PTake a screenshot by hand.
      
          
      
        
      

        
      
          
      Keyboard shortcuts
      
          
      
            
      SpacePlay or pause the video
      
            
      ← →Move the video 5 seconds (hold Shift for 10)
      
            
      + − 0Zoom the Flow timeline in, out, or back to the whole recording
      
            
      Ctrl+ZUndo the last edit
      
            
      Ctrl+Y / Ctrl+Shift+ZRedo
      
            
      ↑ ↓ (Steps)Previous or next step of the open run
      
            
      Enter (Steps)Rename the selected step
      
            
      S / M (Steps)Split the selected step, or merge it with the next step of its run
      
            
      Ctrl+Enter (Steps)Confirm the open run
      
            
      ?Open this help
      
            
      EscClose this help
      
          
      
          
      Undo covers every edit (steps, markers, document sections, maps), up to 50, until you open another session.
      
          
      Clicks
      
          
        
            
      • Click a band, a marker or a screenshot on the Flow timeline to go to that moment.
        • 
            
      • Right-click the Flow timeline to insert a Start or End marker there.
        • 
            
      • While an analysis runs, its log shows with a Cancel button that stops it.

      Common issues
      
          
      
            
      A recording key did nothing
      
            
      Another program on the SME's computer may use the same keys. Close it and press the key again, or use Start next run and End run in the capture app's tray menu.
      

            
      A Citrix or remote desktop window shows as one app
      
            
      The recorder cannot see inside a remote window from the SME's computer, so the work done in it shows as one app with no steps inside. Run the capture app inside the remote session, or rely on the run markers and a video for that part.
