      How to use
      
        
      
      
      
      
        
        
        
        
        
        
        
        
        
        
        
      
      
      
      

        
      
          
      What is a transaction?
      
          
      A transaction is one pass through the process: one order entered, one ticket handled. The SME records the process a few times and presses the transaction key (or the recording bar's button) at the start of each transaction. A project made from a video, or an empty one, is one transaction until you mark where each one starts on the Timeline (an empty project has a timeline once you attach a video).
      
          
      From a recording to the PDD
      
          
      The SME sends you a zip of the recording (the capture app's end summary makes it). Unzip it (right-click it, Extract All), then open the folder with Open project: the folder Extract All makes opens too, since it holds the recording folder. You confirm the first transaction's drafted steps, review how the other transactions differ, write the document and export the PDD. The Overview's Checklist ticks what is done, with one button for the next act.
      
          
        
            
      1. Transactions. Open the project: the app analyzes the recording by itself and drafts each transaction's steps and the map (the bar at the top says so while it works). Each transaction starts at a start marker; if one is missing, right-click the Timeline at that moment, choose Start a transaction here and click Apply marker changes.
        2. 
            
      2. Reference transaction. In Steps, check transaction 1's drafted steps against the screenshots or the video. Fix the boundaries (merge, split, add, hide), name the steps the way the document should, write a description where a step needs one, then click Confirm transaction.
        3. 
            
      3. Other transactions. The other transactions arrive drafted and named like the reference transaction. Open each one in Steps: it lists how it differs from the reference transaction (extra, skipped or reordered steps). Fix a step where needed; the other transactions are not confirmed.
        4. 
            
      4. Document. On the Overview, you write the document fields: title, purpose, scope, trigger, result, contacts, business rules, exceptions and the improvement and automation scope. The PDD prints them in place of its placeholders.
        5. 
            
      5. PDD. Export the PDD (.docx); every export opens its folder with the file selected. Its process map is the one the Map shows first: your edited As-Is map when you made one (on the Map, Edit as the As-Is map), else the process map. Edited maps lists your copies; Delete takes one out with its file, and Ctrl+Z brings both back.
        6. 
          
      
          
      Every change you make saves itself to the project folder: the top bar says Saved, and pointing at it shows the folder. That folder holds the whole project, with its video, transcript, screenshots, attachments and edited maps. To hand the project to someone, use Export, Whole project (.zip): one zip of the folder, made next to it.
      
          
      Several projects. Open, Open in a new window (or the button beside a recent project) opens another project beside this one; a project already open in another window opens read only, and says so. Closing a window closes only its project.
      
          
      What the Overview shows
      
          
        
            
      • Checklist: the five acts above, each ticked once it is done. The export is never ticked: the app keeps no record of it. When the As-Is map the PDD prints was made before the steps changed, it adds Check the As-Is map: check it, or make it again with Copy again on the Map.
        • 
            
      • Document: you write these fields; the PDD prints them. Its line names the fields still empty.
        • 
            
      • From the transcript: what was said outside the transactions, from the meeting transcript you attached; the app places each sentence by its time.
        • 
            
      • Observations: the app measures these from the recording, and the PDD prints the same rows in its sections 5 and 6: Data (every field entered, with its system, its step and an example value, and the Re-keyed data: a value typed again in another system) and Applications and time (the time of each transaction, and each system's screens, steps and time per transaction). They are measured again with each analysis and each PDD export, and as the Overview opens after a change of the steps (From the last analysis; refreshing says so meanwhile; typing in the document stops it, and the next opening measures them).
        • 
          
      
          
      Optional inputs
      
          
        
            
      • A video of the recording, for example a Teams recording: attach it on the Overview (the line under the Checklist) or on the Timeline's video band, to check the steps against it and hear the SME explain. You sync it as you attach it: pause it at a moment you recognize, click Mark frame, then click the same moment on the timeline. It is copied into the project folder, so the folder carries it. Remove, beside it on the Overview (or Remove video beside Sync video on the Timeline), takes the video out of the project with its copy in the folder; Replace takes out the copy it replaces. Ctrl+Z brings it back.
        • 
            
      • A meeting transcript (.vtt or .docx): attach it on the Overview (the line under the Checklist). Its sentences show beside the document fields, and with each step once the transcript is placed in time: a synced video places it, or use Sync on the Timeline's Transcript lane (pick a sentence, then click where it was said). A sentence said before the recording started shows how long before (for example 0:28 before). A sentence you add to a step's description or a field is printed in the PDD. Remove takes the transcript out of the project with its original file; Ctrl+Z brings them back.
        • 
          
      
          
      Starting without a recording
      
          
      In the New menu, New project from a video makes a project from a video of the process (a Teams recording, a screen video): the video is copied into the new folder and the Timeline follows it. New empty project makes a project with nothing in it. Either is one transaction until you mark where each one starts on the Timeline; an empty project has a timeline to mark them on once you attach a video. Add its steps in Steps with + Add step (Alt+Up and Alt+Down move a step without a time), or on the Timeline with + Step at the video's playhead. The step pane's System field says which system a step happens in.
      
          
      Screenshots, notes and attachments
      
          
      In the step pane, Add screenshot takes a frame of the video, a pasted image (Ctrl+V in the pane) or an image file. Use in PDD picks the one the PDD prints under the step; Remove takes one off (a recorded screenshot stays in the recording). A note belongs to a step (the step pane) or to a moment (right-click the Timeline, Add note here). The PDD leaves notes out, in its text and in its map pictures; the Map shows a step's notes beside the step (an edited As-Is map shows the notes it was copied with), and so do Export's map image and BPMN file. Attach file in the step pane and Add file under the Overview's document fields copy a file (an example email, a spreadsheet, an SOP) into the project folder, and the PDD lists them. Ctrl+Z undoes each of these.
      
        
      

        
      
          
      Transactions and drafted steps
      
          
      A transaction is one pass through the process, from a start marker to its end marker. The app drafts every transaction's steps: a step is one visit to a screen, and it ends at the action that commits the work there (Save, Search, Submit, Send) or where the work moves to another screen. Steps lists the transactions in time order; open one to see its steps. Steps outside every transaction are listed under Outside the transactions.
      
          
      Confirm the reference transaction
      
          
        
            
      1. Open the reference transaction: transaction 1, marked Reference, unless you choose another one (right-click a transaction, Use as reference transaction).
        2. 
            
      2. Check its steps against the screenshots or the video. Where a boundary is wrong, merge, split, add or hide steps (right-click a step, or use the step pane).
        3. 
            
      3. Name the steps the way the document should: double-click a name, or select the step and press Enter. In the step pane the name is saved when you press Enter or leave the field, the description when you leave it; there is no Save button, and Ctrl+Z undoes each change. A step's description is printed with it in the PDD.
        4. 
            
      4. Click Confirm transaction: the steps you did not change are accepted as they are. Undo confirm, beside the Confirmed badge, turns them back into drafts.
        5. 
          
      
          
      The step panel
      
          
      Select a step in Steps, click a box on the Map or a step band on the Timeline: the step panel opens beside it. It shows every time the step happens in the transactions, each with its moment (▶ plays it in the panel's own video), its screenshots, what was said and its notes. Watch in the step pane plays the step there.
      
          
      Fixes that carry to the other transactions
      
          
      A name you give a drafted step goes at once to the same drafted steps in the other transactions (each transaction says in one line how many of its names came that way). A merge in the reference transaction is also made in the other transactions wherever they have the same drafted steps one after the other, and one Ctrl+Z undoes all of it. Hiding a drafted step offers to hide it in every transaction. Splits and added steps are made in each transaction that needs them.
      
          
      Differences between transactions
      
          
      Every other transaction is compared with the reference transaction step by step, the way the PDD compares them: an open transaction lists its extra steps (and where they happen), its skipped steps, the steps done in a different order and the steps done more often than in the reference transaction, and its line counts them. Said apart, above them: when part of it was left out of the analysis, which part, and a step that happens only under a condition (Only when) and was not done, which is no difference. The other transactions are not confirmed: once the reference transaction is confirmed and each other one has been opened, the Overview's Checklist ticks Review the other transactions.
      
          
      Sub-processes
      
          
      A step can hold steps of its own: a sub-process. Open as a sub-process, in the step pane, gives a step one step per action recorded in it (a field typed, a click); Group into a sub-process, in the Steps toolbar once two or more steps one after the other are ticked, moves them into a new one. Either is made in every transaction. The ▸ N sub-steps button on its row opens it, one block per transaction that goes through it, and the line above the list goes back up. Dissolve sub-process undoes it, and Ctrl+Z undoes that. Confirm transaction confirms every level.
      
          
      The flow of the steps
      
          
      After a step the next one follows. Where the process branches or loops, say so in the step pane's Flow line: Only when gives the step a condition (the map draws a decision, with an "otherwise" path around it); Go to sends the process back to an earlier step, on to a later one or to its end, when a condition holds. Inside a sub-process the flow stays inside it: its end ends the sub-process.
      
          
      The activity library
      
          
      The step pane's Name offers the activities of the step's system from the activity library: pick one and the step takes its name and its system, and its description when you wrote none. You can still type any name. A project keeps the library it started with: its first analysis copies the app's library into the project folder as library.json. The app's library is the file library\activities.json in the app's resources folder; Build the library makes a new one from the names given in projects and hand-offs.
      
          
      
          
      What the step labels mean
      
          
      A step shows its label only where it differs from its transaction: the reference transaction's status (Draft or Confirmed) says it for the others, and a drafted step of another transaction shows none. Steps outside every transaction show theirs.
      
          
        
            
      • Draft drafted by the app and not checked yet; every analysis drafts it again.
        • 
            
      • Confirmed you accepted the draft as it is.
        • 
            
      • Edited you changed its name, its boundaries or its flags.
        • 
            
      • Added you added it by hand.
        • 
            
      • Hidden you took it out; Show hidden steps on its transaction lists it again.
        • 
          
      
          
      Every analysis keeps confirmed, edited, added and hidden steps as they are.
      
          
      Leaving things out
      
          
        
            
      • Apps outside the process, in the Steps toolbar: tick the apps that are not part of the process, for example Teams or Outlook used during the call; the steps and the map are updated without them.
        • 
            
      • Leave out of the analysis, on the Timeline: Shift-drag across a stretch (a break, a detour) and choose it on the card that opens. The steps and the map are drafted again without that stretch, and its time is not counted; a transaction with a stretch left out says so, and the reference transaction's steps done in it are not read as skipped. The Timeline shows the stretch hatched, Left out of the analysis: click it and choose Include again to bring it back. Ctrl+Z undoes either.
        • 
            
      • Hide step: takes one step out, and no analysis brings it back. Only a step you added can be deleted.
        • 
          
      
          
      Waste
      
          
      Flag a step as Waste when it should not be needed (rework, duplicate effort). The PDD prints the flag with the step, and the maps mark it: a dashed box on how the transactions ran, a Waste note beside its task on the process map. Branches and exceptions are not flags: the map and the differences between the transactions show them.
      
        
      

        
      
          
      What the Map shows
      
          
      The Map shows the map the PDD prints: your As-Is map when you made one, else the process map the app draws from the reference transaction and the others, a box per step in its system's colour, with its notes and files beside it. The line above the map says which one shows. Show how the transactions ran draws the map from the transactions as they ran: hover a line for how often it was taken and its time; a dashed line is a path set in Steps that no transaction took. Click a box for the step panel. Fit fits the map in view, and Reset layout puts back the boxes you dragged.
      
          
      Sub-processes
      
          
      When a step holds a sub-process, Map: above the map chooses the main process or a sub-process; its number is its chapter in the PDD, and Steps shows the same level. On the process map, the arrow on a sub-process opens its map; on how the transactions ran, a double-click on a box marked + does.
      
          
      Your As-Is and To-Be maps
      
          
        
            
      • Edit as the As-Is map copies the process map into the editor, and the PDD prints the copy in its place. Change it there (Ctrl+Z and Ctrl+Y undo and redo in the editor); it is kept once you change something, and analyzing the project again never changes it. When the steps change after it was made, the Map says so, with Copy again.
        • 
            
      • Edit a new copy, once the As-Is map exists, starts another copy: choose To-Be map in Use in PDD as, and the PDD prints it under its improvement scope.
        • 
            
      • Edited maps lists your copies: Edit, Use in PDD as (None, As-Is map, To-Be map), Duplicate, Copy again and Delete (Ctrl+Z brings a copy back).
        • 
          
      
          
      Exporting the map
      
          
      Export, Process map (image) saves the map the Map shows as an SVG image, for Figma, Lucidchart or a browser. Process map (BPMN) saves it as a BPMN 2.0 file, with every sub-process, for ADONIS, Bizagi or Camunda. Both keep the steps' notes, which the PDD's pictures leave out.
      
        
      

        
      
          
      Working with markers
      
          
      A transaction starts at a start marker and ends at its end marker; the SME places them with the recording bar or the recording keys. An edited marker changes the transactions once you apply it; the recording itself never changes.
      
          
        
            
      • Add: right-click the timeline at that moment and choose Start a transaction here or End the transaction here.
        • 
            
      • Rename, move or delete: in the Timeline's Markers panel. Double-click a Start marker to rename it.
        • 
            
      • Apply: a changed marker shows at once as pending. Apply marker changes, in the bar at the top, updates the transactions, the steps and the map.
        • 
          
      
          
      To join two transactions, delete the End of the first and the Start of the second. To split a transaction, start a transaction where its second part begins: a Start ends the transaction before it.
      
        
      

        
      
          
      What to tell the SME
      
          
      The SME records with the capture app on their own computer. These keys mark the transactions while recording:
      
          
      
            
      Ctrl+Shift+SThe transaction key: start the next transaction (Transaction 1, Transaction 2, and so on). Ends the previous transaction first, and starts the recording if none is running.
      
            
      Ctrl+Shift+EEnd the current transaction.
      
            
      Ctrl+Shift+PTake a screenshot by hand.
      
          
      
          
      The recording bar on the SME's screen does the same without the keys: Start recording, then Next transaction for each transaction, Pause and Stop. End transaction is in the capture app's tray menu.
      
        
      

        
        
      
          
      Handing a version to the developers
      
          
      Export, Hand off... asks what changed in this version, then makes one zip next to the project folder, named after the project and its version (for example Order entry v2.zip): the whole project, with the PDD and the Technical details of that version. Each hand-off gets the next number, and the PDD says which version it is: its Document control reads Version 2, handed off with the date and your name, over a table of every version and what changed. A PDD exported between hand-offs reads Working copy after version 2. Ctrl+Z takes a hand-off's version back; its zip file stays where it is.
      
          
      Opening a hand-off
      
          
      A developer opens the zip with Open, Open a hand-off (.zip) (a button on the page shown while no project is open, too). The app keeps its own copy and opens it read only: everything can be looked at and played, and nothing can change. A hand-off unzipped by hand opens read only too. The Overview's project line reads the version, the date and who handed it off; Export opens the PDD and the Technical details the zip came with. A newer version is a zip of its own, opened the same way.
      
          
      The Technical details
      
          
      A spreadsheet of what the recording holds for a developer: every click, entry and choice of the reference transaction with the control it acted on and how the recorder identified it, every field with what was entered in each transaction (a password was never recorded), the values typed again in another system, and the programs. Export, Technical details (.xlsx) writes it on its own too.

      Clicks
      
          
        
            
      • Click a band on the timeline, or a marker in the Markers panel, to go to that moment. Click a screenshot to see it full size.
        • 
            
      • Click a step band on the timeline to open the step panel beside it.
        • 
            
      • Right-click the timeline to start or end a transaction there, or to add a note at that moment. Click a hatched stretch, left out of the analysis, to include it again.
        • 
            
      • On the Map, in how the transactions ran, drag a box to move it; Reset layout, beside Fit, puts the boxes back where the map lays them out.
        • 
            
      • While the steps and the map are updated, the bar at the top says so, with Cancel. An update changes the project only when it finishes, so Cancel leaves the steps and the map as they were.

      Common issues
      
          
      
            
      A recording key did nothing
      
            
      Another program on the SME's computer may hold the same key. The capture app says so when it starts: Keys changed names the key it uses instead, Keys not available means there is none. Use the recording bar (Start recording, then Next transaction) or the tray menu (Next transaction, End transaction), or close that program and start the capture app again.
      

            
      A Citrix or remote desktop window shows as one app
      
            
      The recorder cannot see inside a remote window from the SME's computer, so the work done in it shows as one app with no steps inside. Run the capture app inside the remote session, or rely on the transaction markers and a video for that part and add its steps by hand in Steps.
      

            
      The annotations for this project cannot be read
      
            
      A banner at the top says so, and nothing is saved while it shows. Restore the newest backup, on the banner, puts back the newest backup that can be read (it asks first and says when that backup was saved) and keeps the file that cannot be read beside it, as annotations.unreadable with the time.
      

            
      The steps or the map are missing or out of date
      
            
      The app analyzes a project by itself when it opens. If that stopped (it was cancelled, or it failed and the log at the top says why), analyze it again. Your confirmed, edited, added and hidden steps are kept.
